Logs, Alerts and SIEM for Beginners

What is a log?

A log is a record of something that happened on a system: a person signed in, a file was opened, a web page was requested, a connection was blocked. Almost everything leaves a log line. For a security analyst, logs are the evidence, a bit like the footage from many cameras.

Where logs come from

  • Operating systems: sign-ins, new accounts, services starting.
  • Web servers: every page request and its result.
  • Firewalls and routers: allowed and blocked connections.
  • Cloud services and applications: who changed what.
  • Security tools: EDR detections, email filter results.

Reading a log line

Most log lines answer the same questions: when, where, who, what and from where. Here is a made-up login log: 

2026-10-20 03:12:01 server1 sshd: Failed password for adaeze from 203.0.113.50
2026-10-20 03:12:04 server1 sshd: Failed password for adaeze from 203.0.113.50
2026-10-20 03:12:07 server1 sshd: Failed password for adaeze from 203.0.113.50
2026-10-20 03:12:10 server1 sshd: Failed password for adaeze from 203.0.113.50
2026-10-20 03:12:13 server1 sshd: Failed password for adaeze from 203.0.113.50
2026-10-20 03:12:16 server1 sshd: Accepted password for adaeze from 203.0.113.50
2026-10-20 09:30:44 server1 sshd: Accepted password for tunde from 198.51.100.7

Read it as a story. Five failed passwords three seconds apart, then a success, all for one account from one address at 3 a.m. That pattern is what a person (or program) guessing passwords looks like. The IP address comes from a range reserved for examples, so it is not a real machine.

Web server logs have a different shape but the same ideas:

198.51.100.7 - - [20/Oct/2026:09:31:02 +0000] "GET /index.html HTTP/1.1" 200 5120
198.51.100.7 - - [20/Oct/2026:09:31:05 +0000] "GET /missing.png HTTP/1.1" 404 190

Here 200 means the page was served and 404 means the file was not found. The status codes are the same ones you met in the REST API guide.

Useful Windows events

On Windows, the Security log records sign-ins with numbered event IDs. Two you will see constantly are 4625, a failed logon, and 4624, a successful logon. Learning a handful of IDs gives you a head start.

What is a SIEM?

Reading logs on one machine is easy. A company may have thousands of machines. A SIEM (security information and event management) system solves this. It:

  • Collects logs from everywhere into one place.
  • Normalises them, so "user" and "username" and "account" become the same field.
  • Stores and searches them, so you can ask "show every login by this user this week".
  • Correlates events across systems to find patterns no single log shows.
  • Alerts when a detection rule matches.

Well-known SIEM products include Splunk, Microsoft Sentinel and Elastic Security. Their search languages differ, but the thinking is the same.

Detection rules

A detection rule describes a suspicious pattern. This is plain-language pseudocode, not any one product's syntax: 

IF   event = "failed login"
AND  same source IP
AND  count >= 5
AND  within 5 minutes
THEN raise alert: "Possible password guessing"
     severity = medium
     then, if a successful login follows from the same IP,
     raise severity = high

False positives and tuning

Rules are never perfect. A user who forgot their password will trigger the rule above, and that is a false positive. Too many false positives cause alert fatigue: analysts get tired and real attacks hide in the noise. So SOC teams tune rules, for example by raising a threshold, ignoring a known scanner, or adding context. A good analyst reports noisy rules rather than just closing them.

Write your own mini detector

Save the sample log above as auth.log and this script next to it as count_failed.py: 

from collections import Counter

failed = Counter()

with open("auth.log") as log:
    for line in log:
        if "Failed password" in line:
            source_ip = line.split(" from ")[-1].strip()
            failed[source_ip] += 1

for ip, count in failed.most_common():
    flag = "  <-- check this one" if count >= 5 else ""
    print(ip, count, flag)

Run python count_failed.py. It counts failed passwords per address and flags any with five or more. Real SIEM rules also look at time windows, but this shows the core idea in a few lines.

Good log habits

  • Keep clocks accurate. If systems disagree about the time, you cannot line events up.
  • Keep logs long enough to investigate something found weeks later.
  • Protect logs. Attackers try to delete them, so copy them to a separate place.
  • Mind privacy. Logs can contain names, addresses and sometimes secrets. Never paste real logs into an online tool. Use made-up samples.

Common beginner mistakes

  • Looking at one log line instead of the pattern around it.
  • Trusting the time without checking the time zone.
  • Assuming "no alert" means "no attack".
  • Closing noisy alerts without reporting them.

Practice project

Extend the script so it also counts successful logins per address, and prints a warning when an address had five or more failures followed by a success. Then write three more fake log lines of your own and test that your script handles them.

Summary

  • Logs record what happened. Read them as a story: when, who, what, from where.
  • A SIEM collects, normalises, searches, correlates and alerts.
  • Detection rules describe suspicious patterns, and tuning reduces false positives.
  • Keep logs accurate, protected and private.
