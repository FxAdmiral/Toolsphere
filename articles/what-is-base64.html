What Is Base64, and Why Isn't It Encryption?

A plain-English guide for beginners, with examples you can try yourself.

Published 25 October 2026 • About 6 minutes to read

The short answer: Base64 is a way of writing data using only ordinary letters, numbers and a few symbols. It changes how data looks, not who can read it. Anyone can reverse it in a second, so it protects nothing.

What is Base64?

Computers store everything as bytes, which are numbers from 0 to 255. Some systems, such as email and parts of the web, were built to carry only plain text. Raw bytes can break them. Base64 solves this by turning any data into a string that uses just 64 safe characters: the letters A to Z and a to z, the digits 0 to 9, and the symbols + and /.

How it works

Base64 takes the data three bytes at a time and rewrites those 24 bits as four groups of 6 bits. Each 6-bit group is a number from 0 to 63, and each number is replaced by one character from the alphabet. So three bytes become four characters.

For example, the three letters Man become TWFu. The word hello becomes aGVsbG8=.

The = at the end is padding. When the data does not divide evenly into groups of three bytes, one or two = signs fill the gap so the length is a multiple of four. Because three bytes become four characters, Base64 text is about one third larger than the original data.

A variant called Base64URL swaps + and / for - and _ so the result is safe inside web addresses. JSON Web Tokens use this version.

Where you will meet Base64

  • Web login headers. With "Basic" authentication, the browser sends username:password as Base64. The text user:pass becomes dXNlcjpwYXNz.
  • Email. Attachments and non-English text are sent as Base64 so mail systems can carry them.
  • Data URLs. A small image can be placed straight inside a web page as Base64 text.
  • Login tokens. The readable parts of a JSON Web Token (JWT) are Base64URL text.
  • Configuration files. Tools such as Kubernetes store secret values as Base64 in their files.

Base64 is encoding, not encryption

This is the most important point, and a common beginner mistake. Encryption uses a secret key, and without the key the data cannot be read. Base64 has no key and no secret. The method is public, and anyone can decode it instantly, with a tool like our Base64 Encoder and Decoder.

Real mistakes that come from confusing the two:

  • Storing passwords as Base64. This is the same as storing them in plain text. Real systems should use a dedicated password-hashing method such as Argon2id, bcrypt or scrypt.
  • Putting an API key or secret in a website's code as Base64 and thinking it is hidden. Anyone who opens the page can read it.
  • Using Base64 to "protect" personal data before sending it. It does not stop anyone from reading it.

Why security analysts decode Base64

Attackers often wrap harmful commands or scripts in Base64 so they are harder to spot at a glance. For example, Windows PowerShell has an option that takes a command as Base64 text. Analysts decode such strings to see what they really do.

Be careful. Decoding a suspicious string only shows you what it says. Never run the decoded result. Read it, and look at it somewhere safe.

One technical note: our tool reads the result as standard text (UTF-8). PowerShell commands use a different text format, so they may look garbled in it. Analysts use specialist tools for those.

Using Base64 in code

In JavaScript, btoa() and atob() encode and decode simple text:

btoa("hello");        // "aGVsbG8="
atob("aGVsbG8=");     // "hello"

These functions fail on characters outside the basic Latin set, such as emoji, and do not use UTF-8 for accented letters. For general text, convert it to UTF-8 bytes first: 

const bytes = new TextEncoder().encode("héllo");
let binary = "";
bytes.forEach(b => binary += String.fromCharCode(b));
const encoded = btoa(binary);   // "aMOpbGxv"

In Python, the base64 module does it:

import base64

encoded = base64.b64encode("hello".encode("utf-8")).decode("ascii")
decoded = base64.b64decode(encoded).decode("utf-8")

Summary

  • Base64 rewrites data as safe text using 64 characters.
  • It makes data about one third larger.
  • It is used in email, web headers, tokens and config files.
  • It is not encryption. Anyone can decode it.
  • Never use it to protect passwords or secrets.
