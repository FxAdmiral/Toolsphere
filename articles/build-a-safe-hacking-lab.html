Build a Safe Ethical Hacking Lab and Practise Legally

Set up a private place to practise, and learn where it is legal to try things.

Why you need a lab

You learn security by doing, but you may only do it on systems you own or have written permission to test. A lab is your own private, isolated setup where nothing you try can hurt anyone else. It is the safe, legal way to practise.

Rule one: use tools and techniques only against your own lab or platforms that invite you to practise. Never point them at a school, workplace, public Wi-Fi network or website you do not own.

What you need

  • A computer with enough memory. 8 GB works for one small virtual machine, and 16 GB is more comfortable.
  • Free disk space, since virtual machine images are large.
  • Virtualisation software such as Oracle VirtualBox, which is free, or VMware's desktop products. Check each product's current licence terms.
  • Or Docker, for running small ready-made apps.

Keep the lab isolated

  • Use a host-only or internal network so lab machines talk only to each other, not to the real network.
  • Take snapshots before experiments, so you can roll back.
  • Never reuse a real password inside the lab.
  • Do not keep personal files on lab machines.
  • Update your host computer normally. A lab does not excuse weak basics.

Practice targets that are meant to be attacked

These are deliberately weak applications and training sites, made for learners:

  • OWASP Juice Shop: a modern web shop full of planted weaknesses, with a built-in score board.
  • DVWA (Damn Vulnerable Web Application) and OWASP WebGoat: classic training apps for web weaknesses.
  • TryHackMe and Hack The Box: online platforms with guided rooms and challenges, many aimed at beginners.
  • picoCTF and OverTheWire: free capture-the-flag games and command-line puzzles.

Read each platform's own rules before you start, because they differ.

Run Juice Shop on your own computer

If you have Docker installed, one command starts it. The 127.0.0.1 part makes it reachable only from your own computer, which keeps it private: 

docker run --rm -p 127.0.0.1:3000:3000 bkimminich/juice-shop

Then open http://localhost:3000 in your browser. Stop it with Ctrl+C, and because of --rm it cleans up after itself.

About Kali Linux and similar systems

Systems such as Kali Linux and Parrot OS bundle many security tools. They are popular for learning, but they are not magic and not necessary on day one. Install one in a virtual machine, not as your everyday system. Every tool in them is dual-use, so the same rule applies: only on your lab.

A sensible learning order

  1. Networking and Linux basics.
  2. How websites work, using the programming guides.
  3. Beginner rooms on a training platform.
  4. Web weaknesses in Juice Shop or DVWA, alongside the Web Security Basics guide.
  5. Capture-the-flag games for fun and speed.
  6. Write up what you learn, because teaching it cements it.

Build a portfolio safely

  • Publish write-ups of lab exercises on GitHub or a blog, with the platforms' permission rules in mind. Many platforms ask you not to publish answers to live challenges.
  • Never publish real vulnerabilities in real companies' systems, or any sensitive data.
  • Show your reasoning and the fix, not only the trick.

Common beginner mistakes

  • Running a vulnerable app on a network other people can reach.
  • Using a bridged network by accident, so a lab machine is exposed.
  • Trying new techniques on a real website "to see if it works".
  • Collecting tools instead of learning how things work.
  • Skipping notes, then forgetting what you learned.

Practice project

Install VirtualBox or Docker, start Juice Shop, and solve its first few beginner challenges. Write a one-page note for each in the template above, including how a developer could prevent it.

Summary

  • Practise only on systems you own or are invited to test.
  • Keep your lab isolated, and use snapshots.
  • Use purpose-built apps and training platforms.
  • Write notes with both the weakness and the fix.
