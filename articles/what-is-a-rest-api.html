What Is a REST API? A Beginner's Guide

What is an API?

API stands for Application Programming Interface. It is a set of rules that lets one program ask another program for something. Think of a restaurant. You do not walk into the kitchen. You read the menu, give your order to a waiter, and the waiter brings back your food. The API is the waiter and the menu: it defines what you can ask for and how.

A web API does this over the internet using HTTP, the same protocol your browser uses to load pages. Weather apps, payment buttons and "sign in with" buttons all work by calling web APIs.

Clients and servers

The program that asks is the client, such as a browser or a phone app. The program that answers is the server. The client sends a request, and the server returns a response. Every web API follows this pattern.

What is REST?

REST (Representational State Transfer) is a style for designing web APIs, described by Roy Fielding in his doctoral dissertation in 2000. When people say "REST API" in everyday use, they usually mean an API with these features:

  • Data is organised as resources, such as users or orders, each with its own URL.
  • The client uses standard HTTP methods like GET and POST to act on them.
  • The server is stateless: each request carries everything needed to handle it, and the server does not remember earlier requests.
  • Data is usually exchanged as JSON.

In practice, APIs follow these ideas to different degrees, so treat REST as a set of good conventions more than a strict rulebook.

Anatomy of a request and a response

A request has a method, a URL, headers and sometimes a body:

GET /users/42 HTTP/1.1
Host: api.example.com
Accept: application/json
Authorization: Bearer YOUR_TOKEN

The server replies with a status code, headers and a body:

HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 42,
  "name": "Ada",
  "email": "ada@example.com"
}

HTTP methods

  • GET reads data. It should not change anything.
  • POST creates something new.
  • PUT replaces something completely.
  • PATCH changes part of something.
  • DELETE removes something.

Status codes

The first digit tells you the outcome:

  • 2xx: success. 200 OK, 201 Created, 204 No Content.
  • 3xx: redirection. The thing you want is somewhere else.
  • 4xx: the client made a mistake. 400 Bad Request, 401 Unauthorized (you are not signed in), 403 Forbidden (you are signed in but not allowed), 404 Not Found, 429 Too Many Requests.
  • 5xx: the server failed. 500 Internal Server Error.

JSON in one minute

JSON (JavaScript Object Notation) is a simple text format for data. It supports strings, numbers, true and false, null, lists and nested objects: 

{
  "name": "Ada",
  "age": 25,
  "skills": ["HTML", "CSS"],
  "active": true,
  "address": null
}

JSON needs double quotes around keys and strings, and does not allow trailing commas. Those two rules cause most beginner JSON errors. You can check your JSON with our JSON Formatter and Validator, which runs in your browser, or with a free online validator such as JSONLint. Never paste real passwords, keys or private data into any online tool. Use made-up sample data instead.

Designing clean URLs

  • Use nouns, not verbs, and plural names for collections: /users, not /getUsers.
  • Let the method say the action. DELETE /users/42 is clearer than /deleteUser?id=42.
  • Use query strings for filtering and paging.
GET     /users            list users
GET     /users/42         get one user
POST    /users            create a user
PATCH   /users/42         update part of a user
DELETE  /users/42         delete a user
GET     /users?status=active&page=2   filter and page through results

Calling an API from JavaScript

The browser's built-in fetch function sends requests. The address below is a placeholder, so replace it with a real API when you practise. 

async function loadUser(id) {
    try {
        const response = await fetch("https://api.example.com/users/" + id);

        if (!response.ok) {
            throw new Error("Request failed with status " + response.status);
        }

        const user = await response.json();
        console.log(user.name);
    } catch (error) {
        console.log("Something went wrong:", error.message);
    }
}

loadUser(42);

Notice the check of response.ok. A 404 or 500 does not make fetch throw an error by itself, so you must check. You can also try an API from the terminal with curl: 

curl -H "Accept: application/json" https://api.example.com/users/42

API security basics

  • Always use HTTPS, so requests cannot be read or changed on the way.
  • Authentication proves who you are, and authorisation decides what you may do. They are different.
  • Never put secret keys in front-end code. Anyone can view a page's source. Secrets belong on the server.
  • Encoding is not protection. Basic authentication sends username:password as Base64, which anyone can reverse. Read What Is Base64, and Why Isn't It Encryption? and try the Base64 tool.
  • Validate every input on the server, and limit how often a client can call the API.

Common beginner mistakes

  • Treating 401 and 403 as the same. 401 means "who are you?" and 403 means "I know who you are, and the answer is no".
  • Forgetting the content type. When sending JSON, set the Content-Type: application/json header.
  • Ignoring errors. Always handle failed requests, slow responses and unexpected data.
  • CORS errors in the browser. Browsers block a page from reading another site's API unless that API allows it. The fix is on the server, not in your page.

Practice project

Build a small page with a button that calls a free public API of your choice, checks response.ok, and shows one field from the JSON result with textContent. Add a friendly message for when the request fails. Then, using what you learned in the Node.js guide, build your own tiny API that returns a list of three items.

Summary

  • An API lets one program ask another for data or actions.
  • REST APIs organise data as resources with URLs, and use HTTP methods.
  • Status codes tell you whether a request worked: 2xx success, 4xx client error, 5xx server error.
  • JSON is the usual data format.
  • Use HTTPS, keep secrets on the server and validate input.
