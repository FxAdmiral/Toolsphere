Git and GitHub for Beginners: Save, Track and Share Your Code

Learn to track every change to your project and publish it safely on GitHub.

Git and GitHub: what is the difference?

  • Git is a program on your computer that records the history of your project. It remembers every saved version, so you can go back.
  • GitHub is a website that stores Git projects online, so you can back them up, share them and work with others. Similar services include GitLab and Bitbucket.

You can use Git without GitHub, but not GitHub without Git. Think of Git as the save history and GitHub as the cloud place you keep it.

Why bother?

  • Undo mistakes. If a change breaks your site, you can return to a version that worked.
  • Experiment safely on a branch without touching your working code.
  • Back up your work off your computer.
  • Collaborate with other people on the same project.
  • Build a portfolio. Employers look at your GitHub profile to see real projects and how you work.

Install Git and introduce yourself

Download Git from the official site, git-scm.com, and install it. Then open a terminal (in VS Code, choose Terminal, then New Terminal) and check it worked: 

git --version

Tell Git who you are. This name and email are attached to your commits:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Be aware that the email in your commits can become public when you push to GitHub. GitHub offers a private "noreply" email address in your account settings that you can use instead.

Your first repository

A repository (or repo) is a project folder that Git tracks.

mkdir my-site
cd my-site
git init

# create or edit some files, then:
git status
git add .
git commit -m "Add homepage"
git log --oneline

These commands move your work through three areas:

  • The working folder is where you edit files.
  • The staging area is where you choose what goes into the next save. git add puts changes there.
  • The repository history is the permanent record. git commit saves the staged changes as a snapshot.

git status shows what has changed, and git log --oneline lists your commits. Write commit messages that say what changed and why, in a short line, such as "Fix broken link in footer". Messages like "stuff" or "update" are no help to you in a month.

Files you must never commit

Create a file named .gitignore in the project root. Each line is a file or folder that Git should ignore: 

.env
node_modules/
.DS_Store
Never commit passwords, API keys or .env files. If a secret is committed by mistake, deleting it in a later commit does not remove it from the history. Treat it as exposed: change or revoke the secret straight away.

Branches

A branch is a separate line of work. You can build a new feature on a branch, and merge it into the main code only when it works. 

git switch -c add-contact-page

# edit files, then:
git add .
git commit -m "Add contact page"

git switch main
git merge add-contact-page

Your main branch is usually called main, though older projects use master. Run git branch to see yours. (If your Git is older than version 2.23, use git checkout instead of git switch.)

Putting your project on GitHub

  1. Create a free account at github.com.
  2. Click New repository. Give it a name, and leave it empty: do not add a README, licence or .gitignore on GitHub, because your local project already has its own history.
  3. Copy the repository address that GitHub shows you, then run these commands in your project folder:
git remote add origin https://github.com/YOUR-USERNAME/your-repo.git
git branch -M main
git push -u origin main

GitHub does not accept your account password for pushing. When you push, sign in through the browser window that Git Credential Manager opens (it is included with Git for Windows), or use a personal access token or an SSH key. GitHub Desktop is another beginner-friendly option.

The everyday workflow

git pull
# ...edit files...
git add .
git commit -m "Describe what you changed"
git push

To copy an existing project from GitHub to your computer, use git clone followed by the repository address.

Common problems

  • "nothing to commit". You have not changed any files, or you forgot git add.
  • "failed to push some refs". The online version has changes you do not have yet. Run git pull, then push again.
  • Merge conflicts. Two changes touched the same lines. Git marks the file with lines of <<<<<<<, ======= and >>>>>>>. Edit the file to keep what you want, remove the markers, then add and commit.

Habits that make a good portfolio

  • Write a README that explains what the project is, how to run it and what you learned.
  • Commit small, often, with clear messages.
  • Keep secrets out, and use a .gitignore from the start.
  • Pin your best repositories to your GitHub profile.

Practice project

Put a small website folder, even your HTML and CSS practice page, under Git. Make three commits with clear messages, create a branch that changes the page colour, merge it, then push the project to a new GitHub repository.

Summary

  • Git records your project's history. GitHub stores it online.
  • Work moves from the working folder, to staging with add, to history with commit.
  • Branches let you experiment safely.
  • Never commit secrets, and use .gitignore.
  • Pull before you start, and push when you finish.
