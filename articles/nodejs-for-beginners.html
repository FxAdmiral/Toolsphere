Node.js for Beginners: Run JavaScript Outside the Browser

What is Node.js?

Normally JavaScript runs inside a web browser. Node.js is a program that lets JavaScript run on your computer or on a server, outside the browser. It uses V8, the same JavaScript engine as Google Chrome.

Node.js is not a new language and not a framework. It is a runtime: an environment that runs your JavaScript and adds abilities browsers do not give web pages, such as reading files and running a web server. It is widely used to build the back end of websites and APIs, and many developer tools run on it.

Install Node.js

Download Node.js from the official site, nodejs.org. Choose the LTS (long-term support) version, which is the recommended one for most people. Then open a terminal and check both programs: 

node --version
npm --version

npm is Node's package manager, which installs code written by other people. You get it together with Node.

Run your first program

Create a file called hello.js with this line:

console.log("Hello from Node.js!");

Then run it from the same folder:

node hello.js

Built-in modules

Node comes with modules for common jobs: fs for files, path for file paths, os for system information and http for web servers. You load one with require: 

const fs = require("fs");

const text = fs.readFileSync("notes.txt", "utf8");
console.log(text.toUpperCase());

Put a file called notes.txt next to the script and it prints the text in capitals. You will see two styles in tutorials: require() (CommonJS) and import (ES modules). Both work, but a file that uses import needs either a .mjs extension or "type": "module" in package.json.

A tiny web server

Save this as server.js:

const http = require("http");

const server = http.createServer((request, response) => {
    response.writeHead(200, { "Content-Type": "text/plain; charset=utf-8" });
    response.end("Hello from ToolSphere!");
});

server.listen(3000, () => {
    console.log("Server running at http://localhost:3000");
});

Run node server.js, then open http://localhost:3000 in your browser. You will see the message. Stop the server by pressing Ctrl+C in the terminal.

Your function runs every time a browser makes a request, and it sends back a response: a status code (200 means OK), headers describing the content, and the content itself. This request and response cycle is the foundation of every web application. The next guide explains it in detail.

npm and packages

Writing everything yourself is slow, so developers share code as packages. In a project folder: 

npm init -y
npm install express
  • package.json lists your project and its dependencies.
  • The node_modules folder holds the downloaded code. It can be huge. Add it to .gitignore and do not commit it, because npm install recreates it.
  • package-lock.json records exact versions. Do commit this one.

Express is the most popular package for building web servers. The same hello server is shorter with it: 

const express = require("express");

const app = express();

app.get("/", (request, response) => {
    response.send("Hello from Express!");
});

app.listen(3000, () => {
    console.log("Express app running at http://localhost:3000");
});

Be careful with packages. Install only what you need, from names you can verify, and check that a package is well used and maintained. Run npm audit now and then to see known problems in what you have installed.

Environment variables and secrets

Settings that change between your computer and a live server, and secrets such as database passwords, should not be written in your code. Read them from environment variables instead: 

const port = process.env.PORT || 3000;

During development, many projects keep these values in a file called .env. That file must be in your .gitignore and never committed. If a secret does get exposed, replace it immediately.

Where Node.js fits in ToolSphere

ToolSphere's tools run entirely in your browser today, so they do not need a server. Node.js will matter when we add features that do, such as storing contact messages or publishing articles from an admin page. Keeping simple tools in the browser, and using a server only when it is needed, is a good design rule.

Common beginner mistakes

  • "EADDRINUSE". Something is already using that port, often an older copy of your server. Stop it with Ctrl+C, or choose another port.
  • Changes do not appear. The server does not reload by itself. Restart it, or use a recent Node version's node --watch server.js.
  • "Cannot find module". You are in the wrong folder, or the package is not installed. Check with pwd or ls, and run npm install.
  • Committing node_modules or .env. Add both to .gitignore first.

Practice project: a time API

Extend your server so that /api/time returns the current time as JSON, and anything else returns a 404 message:

const http = require("http");

const server = http.createServer((request, response) => {
    if (request.url === "/api/time") {
        response.writeHead(200, { "Content-Type": "application/json" });
        response.end(JSON.stringify({ time: new Date().toISOString() }));
        return;
    }

    response.writeHead(404, { "Content-Type": "text/plain; charset=utf-8" });
    response.end("Not found");
});

server.listen(3000);

Visit http://localhost:3000/api/time. You have built a tiny API. Then try adding a second route of your own.

Summary

  • Node.js runs JavaScript outside the browser.
  • Built-in modules handle files, paths and web servers.
  • A server answers requests with responses.
  • npm installs packages, so choose them carefully and keep node_modules out of Git.
  • Keep secrets in environment variables, never in code.
